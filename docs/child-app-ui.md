# 子应用 UI 规范

适用于 Lingrove 的全部子应用。新增界面必须遵循；修改现有页面时同时检查受影响区域。参考 Sentra、Glyphora、Kotoba 的一致导航外观，公共实现位于 `packages/host-sdk/src/ui.css`，Lector 已接入。

## 宿主与标题栏

- 一级页直接呈现业务内容，不添加重复的应用名、Logo、欢迎语或品牌标题栏。业务章节标题可以出现在内容区。
- 宿主 Home 在 WebView 左上角：左距 16px、上距 8px、按钮 44×44px。顶部至少保留 60px 操作区；左侧至少空出 64px，右侧可放导入、目录等业务操作。不要重复叠加状态栏 inset；宿主已处理顶部系统安全区。
- 使用 `lingrove-root-actions` 或无内容的等高留白。首页正文从该区域下方开始，不能被 Home 挡住。
- 一级页初始化及返回时调用 `setRootPage(true)`；阅读、查询结果等二级页调用 `setRootPage(false)`，避免原生 Home 与子应用返回重叠。
- 二级页使用 60px 的 `lingrove-secondary-toolbar`，左侧返回点击区域至少 44×44px。必要的文章标题属于正文，不恢复一级品牌栏。
- 默认二级页隐藏底部主导航。模态弹层不作为独立顶层页面；所有弹层需可关闭、可滚动并支持键盘焦点与 Escape。

## 弹层滚动与关闭

- 所有 sheet 的 × 关闭按钮统一使用公共 `lingrove-sheet-close` 样式，以“导入文本”sheet 为标准：38×38px、圆形柔和底色、24px 关闭符号、无边框及阴影。禁止各应用单独覆盖外观；颜色跟随语义主题变量。头部内定位可按布局保留。

- 关闭按钮所在的头部与滚动正文分开：弹层使用纵向 flex 和 `overflow: hidden`，头部 `flex: none`，正文 `min-height: 0; overflow-y: auto`。已有可靠的 sticky 头部可以保留。
- 不要把绝对定位的关闭按钮直接放在整个弹层的滚动容器中；长内容滚动到底时，关闭按钮仍须可见、可点击。
- 保留各弹层现有关闭逻辑与焦点恢复；修复布局不改变遮罩点击行为。
- 手机窄屏和长内容下验证顶部、底部滚动位置，浅色和暗黑模式均不遮挡正文。

## 底部导航

新应用在应用样式之后导入 `@lingrove/host-sdk/ui.css`，使用 `<nav class="lingrove-bottom-tabs" aria-label="主导航">`，按钮以 `aria-current="page"` 表示当前页面。不要覆盖公共导航的按钮几何参数。

| 项目 | 规范 |
| --- | --- |
| 容器 | 居中，最大 660px，模糊 18px，1px 边框，底部无边框 |
| 内边距 | 上 9px、左右 10px、下 `9px + env(safe-area-inset-bottom)` |
| 按钮 | 等宽，最小高度 52px，圆角 10px，内边距 5px 2px |
| 排列 | 图标在上、文字在下，间距 4px |
| 图标 | 23×23px，线宽 1.65，圆端点与圆连接，无填充 |
| 文字 | 11px；选中项字重 600 |
| 选中态 | `--accent` 文字与图标，`--soft` 背景，不能只有文字变色 |
| 宽屏 | 容器顶部圆角 18px |
| ≤760px | 去掉容器圆角及左右边框 |

固定导航页面内容至少留出 `100px + env(safe-area-inset-bottom)` 底部空间。已有应用若使用全高 flex 布局，可保留布局内导航，只要几何外观一致且正文不被遮挡（Sentra 使用此方式）。

## 浅色与暗黑模式

跟随 `prefers-color-scheme`，它在 WKWebView 中反映宿主外观设置。不要建立独立且与宿主冲突的主题开关。

- 根节点声明 `color-scheme: light dark`；浅色与暗黑的 `theme-color` 分别声明 media。
- 使用语义颜色变量：正文、画布、卡片、强调色、强调色上的文字、次要文字、分隔线、柔和选中背景、导航背景、工具栏背景、焦点、错误提示、遮罩等。不能在组件里直接写浅色白底或深色文字。
- 公共导航需要 `--accent`、`--muted`、`--soft`、`--line`、`--nav-bg`；公共工具栏使用 `--toolbar-bg`。
- 暗黑模式应同时覆盖导入菜单、输入框与原生控件、底部导航、词语解释弹层、标记、假名读音、短语下划线、空状态与错误状态。
- 参考 Glyphora 的暗黑配色：画布 `#151c19`、卡片 `#202a24`、正文 `#e3ebe1`、次要文字 `#a8b6a6`、强调色 `#b3d3a4`、柔和背景 `#2e3e32`、分隔线 `#3b493e`。语义有区别时可扩展变量，需保证对比度。

## 焦点与触摸

子应用必须区分触摸与键盘输入。WebKit 在 `dialog.showModal()` 自动聚焦关闭按钮时，也可能匹配 `:focus-visible`；单独使用此伪类会出现触摸打开弹层就带外圈的问题。

- 挂载时调用 SDK `installFocusMode()`，卸载时调用返回的清理函数；并在应用样式之后导入公共 `ui.css`。
- 公共逻辑在 `pointerdown` 捕获阶段清除键盘模式，仅在 Tab、方向键、Home、End 导航时开启。程序自动聚焦不视为键盘导航。
- 焦点环和其他仅用于键盘焦点的视觉效果需限定在 `data-keyboard-focus='true'` 下。浅色和暗黑使用语义焦点颜色。
- 保留弹层自动聚焦、焦点限制、关闭后的焦点恢复和 Escape。不能以 `blur()`、删除可聚焦性或全面禁用键盘轮廓解决外圈问题。
- 验收触摸打开、键盘 Tab 打开、键盘切回触摸以及弹层关闭后的焦点恢复。

## 验收

1. 手机宽度检查浅色与暗黑的一级页、二级页、菜单及弹层。
2. 一级页左上角留给原生 Home，二级页无双重返回按钮。
3. 选中导航有柔和背景；上下安全区不遮挡正文或操作。
4. 注音、下划线、弱化文字、输入框、错误提示在两种主题下都清晰。
5. 检查外观切换会即时生效；语义和内容不因主题改变。
6. 运行相关类型检查及行为测试，按根 AGENTS.md 完成 Debug 构建与需要的真机安装。视觉参数调整不必添加只复述 CSS 的测试。

## App 语言

- 宿主统一提供“跟随系统”、简体中文、英语、日语。子应用通过 SDK 读取规范化语言；所有中文区域映射为简体中文，其他未支持语言映射为英语。
- 子应用启动时调用 `initializeAppLanguage()`；Vue 页面使用 `@lingrove/host-sdk/vue` 的 `useAppI18n()`，让已打开页面响应宿主语言变更，保留输入、导航与学习进度。
- 界面文案（含无障碍标签、提示、内置教材）统一维护在 `packages/host-sdk/src/locales/messages.json`，使用 `t()` 渲染。选择项显式设置稳定的 `value`，不以翻译后的标签作为存储值或业务判断条件。
- 原文、用户标题和历史模型结果保持原内容；新生成的释义、解释与成分翻译跟随 App 语言，学习目标语言单独选择。缓存分析必须校验生成语言；切换语言不能误用其他语言缓存。
- `npm run build` 同步生成宿主 `Localizable.xcstrings`。验收语言切换、长文案的窄屏布局、输入保留、选项值不变和缓存语言隔离。
